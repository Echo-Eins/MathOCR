## 2. Как читать результаты
- **Сначала проверить измеритель.** Прогнать открытую модель с опубликованным баллом (Falcon OCR 1.5 или Surya-OCR-2) нашим
  стендом olmOCR-Bench и получить её число ±1 — как с `unimer_protocol.py` у формул. Без этого наши числа не значат
  ничего.
- **Метрики своих тестов:** CER / WER, NED страницы; порядок чтения (тау Кендалла по строкам); **пропуски и повторы
  целых строк** (главные сбои длинного вывода: модель «теряет место»); CER по высоте страницы (растёт к низу — теряет
  место; по краям — разрешение); отдельно — мелкий текст, многоколоночный, формулы (CDM), таблицы (TEDS).
- **Механизм полезен**, только если при равном вычислении он лучше простой основы хотя бы на двух из: общий балл,
  мелкий длинный текст, многоколоночный, CER рукописи — и не хуже на остальных. Как у формул: по одному изменению,
  стенд на подвыборке, многосидовые прогоны — только в конце.
- **Диагностика механизмов** (инструменты формул переносятся): след указателя кросс-внимания (монотонно ли идёт по
  строкам, где прыгает), фовеа — рост CE при обнулении (у формул +2 %: «следует, но не нужна»), эффективное поле
  энкодера на странице (`encdec_probe.py`), линейный зонд глифов, учительское принуждение (видимые токены — путь
  к ошибке разбора или распознавания).

## 5. Архитектура (своя, с нуля; без чужих предобученных энкодеров — заявка об эффективности по данным)
Основа — наша формульная модель, масштабированная на страницу **без сжатия на энкодере**: разрешение задаётся
размером глифа (наш `glyph_height`, цель 18–22 px), а не размером страницы.
- **Энкодер (~45 M):** свёрточный ствол 3×3 → TriScan `hv` (скан всей строки в обе стороны + свёртка по всей высоте:
  линейно по клеткам, строка — главная единица страницы) → блоки AAS (ECRA5, сдвиговое внимание вдоль осей, линейно) →
  локальное оконное внимание; полного внимания по 68–136 тыс. клеткам нет. Плюс малая грубая память (пулинг 1/16 —
  строки и блоки) для «куда дальше».
- **Декодер (~65 M, d 768, 8 слоёв):** кросс-внимание **локальное вокруг указателя чтения** (окно памяти у текущей
  строки ± соседние) + грубая память целиком (переходы строк и колонок) + **фовеа** — глимпсы полного разрешения
  ствола для мелкого текста (`fovea_*` уже в коде); самовнимание по выводу (1–2 тыс. BPE-токенов на страницу).
- **Кольцевое семейство (всё уже в `model.py`; на формулах нейтрально — память там ничего не теряла):**
  `ring_bias` (выученная добавка «кольцо × 4 направления» вокруг фокуса предыдущего слоя; выучила профиль +0,8 / −1,0)
  → на странице это и есть указатель чтения («вправо» — следующий символ, «вниз» — следующая строка), мягкая добавка
  становится жёстким окном вокруг фокуса; `coverage` (штраф за прочитанное; сила до 1,8) → прямо против пропусков и
  повторов строк, считать по строкам; `deform_layers` и `RingFovea` (кольцевая CNN заказчика) → мелкий текст и
  грубая память 16×8 (×4 дешевле, §6), детали — из колец полного разрешения; `rings` (ветви 1–8 в стволе) → разброс
  кеглей. **Прецедент против:** «грубый энкодер + фовеа» на формулах провалился (`m_foveac2_s1`: EM 0,000 — детали
  не вернулись). Отличие страниц — синтетика даёт точные рамки слов: указатель и фиксации фовеа можно учить
  вспомогательной потерей (смотреть на слово, которое сейчас выводится), а не ждать, что выучатся сами.
- **Токенизатор:** byte-level BPE ~16 тыс. на нашем корпусе (Markdown + LaTeX + HTML), позже — расширение под русский.
- **Обязательная основа для сравнения** (требование заказчика): тот же декодер на уменьшенной странице (длинная сторона
  1024) и на нарезке — цена «без сжатия» должна быть измерена, а не предположена.
- Инициализация ствола и TriScan весами формульной модели — отдельная абляция. «Полушария» — на этапе разворотов.

## 5a. Структура страницы → локальные операторы (идея заказчика, 2026-10-28): вопросы и тесты
**Идея.** Сначала структурный проход крупными ориентированными операторами (горизонтальным и вертикальным): число
строк, начала / концы, длина и высота строк. Его результат — напрямую или через пулинг — получает переработанный
сложный слой локальных операторов (обычные ядра, кольца, фовеа, AAS, деформируемое чтение, приоритеты внимания —
конфигурации перебираются), чтобы локальная работа опиралась на структуру. **Проблема (заказчик):** без пулинга или
обмена между локальными операторами (кросс-внимание, композиционный AAS) локальность остаётся — знание о строках
помогает лишь ядрам, которые сами видят, например, начало строки. В нашем коде TriScan `hv` — такая пара операторов,
но потоки идут параллельно (клетка после блока знает свою строку и свой столбец, не страницу); страницу даёт только
композиция (второй блок, обмен). На формулах обмен (`pool_exchange`, `exchange`) нейтрален на 5 эпохах — там
структура тривиальна; здесь это центральный вопрос.
1. **Доходит ли знание до каждой клетки** (проверка опасения напрямую): линейный зонд после каждого слоя энкодера —
   номер строки, число строк, длина строки, расстояние до начала и конца (ответы — из рамок синтетики); карта
   точности по странице: провал в середине / конце строк или внизу = знание осталось локальным.
2. **Явная структура или неявная:** структурная голова со вспомогательной потерей против того же числа параметров
   без неё; пропуски / повторы строк, порядок чтения, CER по высоте страницы.
3. **Разнесение структуры по локальным операторам** при равном вычислении: (а) никак; (б) глобальный пулинг + FiLM;
   (в) дескриптор строки, разнесённый вдоль своей строки; (г) кросс-внимание «клетка → токены строк» (68 тыс. × ~60);
   (д) композиционный AAS (x, затем y); (е) раунды обмена TriScan — по зонду п. 1 и метрикам чтения.
4. **Сложный локальный слой:** перебор конфигураций (ядра, кольца, фовеа, AAS, деформируемое, `ring_bias`) с
   условием на структуру (FiLM / гейт); микропробы в 1 эпоху на стенде → полные прогоны лучших.
5. **Структура для декодера:** «где начинается следующая строка» — указателю при переводе строки; точность прыжка
   указателя в концах строк с дескрипторами строк и без.
**Стенд:** ~20 тыс. синтетических страниц с точными рамками строк и слов в уменьшенном разрешении + задача на дальние
связи (Pathfinder-подобная) — распространение информации отдельно от чтения.

## 6. Вычисления — главный риск
Замер на формулах: 3,0 Мпикс/с и 4,9 тыс. токенов/с у модели 43 M. Страница A4 — 2,2 Мпикс (150 dpi; 68 тыс. клеток
при шаге 8×4) … 3,9 Мпикс (200 dpi), 1–2 тыс. токенов. Для модели ~120 M с линейным энкодером оценка **~0,5 страницы/с →
эпоха 200 тыс. страниц ≈ 4–5 суток на ноутбуке**. Что с этим делать (решение заказчика):
1. учебный план как у DAN: строки → абзацы / колонки (кропы 512×1024) → целые страницы только в конце;
2. грубый шаг памяти (16×8) + фовеа для деталей — проверяется пробой против 8×4;
3. аренда GPU для основных прогонов (H100 ≈ 3–4× ноутбука).
